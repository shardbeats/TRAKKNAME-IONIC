# MAINTENANCE — TRAKKNAME Mobile (Ionic)

Operations handover. Read before building releases, touching signing, icons, or seed.

## Environment (pinned — don't reinstall blindly)
- Node via `C:\nodejs` (`npm.cmd`/`npx`; prepend to `PATH` in each terminal).
- Temurin JDK 21 + user-level `JAVA_HOME` (`setx`). Gradle uses `org.gradle.java.home` in `android/gradle.properties`; the SDK path comes from `android/local.properties`. Both files exist on purpose — don't delete them.
- Android SDK: platforms 34–36 + build-tools. App: `com.trakkname.trakkname`, Capacitor 8, `@capacitor/android@8.5.2` (same as core).
- **Fresh terminals**: already-open ones don't see a newly saved `JAVA_HOME`. On `invalid source release: 21` or `JAVA_HOME is not set`, open a new terminal.

## Routines (strict order)
```powershell
$env:PATH = "C:\nodejs;" + $env:PATH
npm run test.unit -- --run   # 27 tests
npm run lint                 # 0 errors (android/ excluded: generated files)
npm run build                # dist/ — always before sync
npx cap sync android         # FROM THE ROOT, never from android/
cd android
.\gradlew.bat clean assembleRelease   # clean is mandatory after asset changes
```
- Quick debug: `assembleDebug` (no `clean` needed without asset changes).
- The `.\` prefix before `gradlew.bat` is mandatory in PowerShell.
- After any `src/` change: build → sync → gradle. Without sync, the APK ships the old UI.

## Signing and releases (secrets)
- `android/app/build.gradle` signs `release` automatically when `android/keystore.properties` exists (`storeFile=../trakkname-release.key.jks`, alias `trakkname`).
- **Never commit**: `*.jks`, `keystore.properties`, `local.properties` (all git-ignored). Back up the `.jks` + password **off-machine** — losing them bricks updates under the same identity.
- Release checklist: 1. tests+lint green → 2. bump `versionCode` in `app/build.gradle` (`versionName` is display-only) → 3. build → sync → `clean assembleRelease` → 4. verify signature with `apksigner verify --print-certs` → 5. publish the APK in GitHub Releases.
- Play Store: same flow with `bundleRelease` (`.aab`).

## Icons and splash
- Source: `assets/icon.png` (1024) + `assets/splash.png` (2732), generated by `assets/make_assets.py` (Pillow) from the desktop artwork.
- **Mandatory order**: 1. `npx capacitor-assets generate --android` (legacy icons + splash) → 2. `python assets/make_assets.py` (overwrites the tool's inset adaptive foregrounds with full-bleed ones; the tool leaves them at ~65% and the icon looks small).
- Pillow lesson: `thumbnail()` **never upscales**, only downscales — use `resize()` with a computed factor to grow.
- Real verification: extract the bitmap from the APK (`res/*.png` are obfuscated in release builds) and look at the foreground, not just `mipmap-*/`.

## Seed and desktop parity
- `seed-json/` is exported from the real desktop DB. After curation changes that alter counts: re-export and verify `manifest.json` — tests pin counts (currently: 18 patterns, 8 enabled).
- Intentional decisions that are **not** bugs (don't "fix"):
  - `Single Noun`/`Una Palabra` removed from the seed in both projects; 1-WORD uses the engine's lone-NOUN fallback.
  - Title in UPPER on screen, copied in original case (desktop parity).
  - No `NOUN` patterns in the style list (permanent filter, covers future imports).

## Architecture (summary)
Agnostic engine via `DbPort` (`lib/engine/types.ts`) → `MemoryDb` (`lib/db`) → tabs consume `useDb()` (`lib/db/store.ts`), never snapshots. Services: `generation` (facade), `settings` (localStorage), `library` (symmetric export/import, accepts desktop backups). Full detail in `README.md` + `TRAKKNAME_IONIC_CONTEXT.md`.

## Don't touch without reason
- `android/gradle.properties::org.gradle.java.home` and `android/local.properties` (environment pins).
- `capacitor.config.ts::appId` (changing it breaks updates: Android treats it as another app).
- `seed-json/*.json` by hand except for one-off causes (source of truth: desktop).
